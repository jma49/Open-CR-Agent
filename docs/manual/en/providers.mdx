On the default runtime, every provider in OpenCode's catalog works except the few [that need code from npm](#providers-that-need-code-from-npm). Name a model as `provider/model` in the model chains ([Configuration](./configuration#models)); the runtime receives only the credentials of the providers they name.

## Providers in OpenCode's catalog

| Provider | Example model | What to set | Tested live |
|---|---|---|---|
| Gemini API | `google/gemini-3.5-flash` | `GEMINI_API_KEY` (or `GOOGLE_API_KEY`, `GOOGLE_GENERATIVE_AI_API_KEY`) | Yes |
| Vertex AI | `google-vertex/gemini-3.5-flash` | `GOOGLE_VERTEX_PROJECT`, `GOOGLE_VERTEX_LOCATION=global`, and application default credentials or `GOOGLE_APPLICATION_CREDENTIALS` | Yes, also keyless from GitHub Actions through workload identity federation |
| Anthropic | `anthropic/<model>` | `ANTHROPIC_API_KEY` | No |
| OpenAI | `openai/<model>` | `OPENAI_API_KEY` | No |
| Amazon Bedrock | `amazon-bedrock/<model>` | `AWS_REGION` and AWS credentials: `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` (with `AWS_SESSION_TOKEN`), `AWS_PROFILE`, or `AWS_BEARER_TOKEN_BEDROCK` | No |
| Azure OpenAI | `azure/<deployment>` | `AZURE_API_KEY`, `AZURE_RESOURCE_NAME` | No |
| DeepSeek, OpenRouter, Groq, Mistral, xAI and the rest of the catalog | `deepseek/<model>` | The provider's key, such as `DEEPSEEK_API_KEY`; for an id ocra does not know, every variable starting with it, such as `GROQ_` | No |

"No": ocra passes the variables and OpenCode does the rest, but no review has run through that provider yet; if one fails, [open an issue](https://github.com/ocrahq/Open-CR-Agent/issues/new/choose). Model ids come from [models.dev](https://models.dev), OpenCode's catalog.

### Providers that need code from npm

For a few providers OpenCode would download its client code from npm on first use, which ocra does not allow during a review. In the catalog of 2026-09-29 these are `aihubmix`, `cloudflare-ai-gateway`, `merge-gateway`, `qvac`, `salad-cloud`, `sap-ai-core` and `watsonx`; their models fail at once with "Failed to initialize provider". If such a service has an OpenAI-compatible endpoint, declare it as [your own endpoint](#your-own-endpoint).

## Your own endpoint

A self-hosted server (vLLM, Ollama, LM Studio) or a company gateway that speaks the OpenAI API is declared in `.ocra/config.json`:

```json
{
  "models": {
    "standard": "gateway/qwen3-coder",
    "light": "gateway/qwen3-small",
    "top": "gateway/qwen3-max"
  },
  "providers": {
    "gateway": {
      "type": "openai-compatible",
      "baseUrl": "https://llm.example.com/v1",
      "apiKeyEnv": "GATEWAY_API_KEY",
      "models": {
        "qwen3-coder": { "input": 0.5, "output": 2, "cachedInput": 0.1 },
        "qwen3-small": { "input": 0.1, "output": 0.4 },
        "qwen3-max": { "input": 2, "output": 8 }
      }
    }
  }
}
```

- **The id** (`gateway`) is yours: lowercase letters, digits and hyphens. Avoid ids in OpenCode's catalog: a declaration replaces the known provider for the run.
- **`baseUrl`** must be `https`, or plain `http` on this machine: `localhost`, `127.0.0.1` or `::1`. For Ollama, for example, `http://127.0.0.1:11434/v1`. It may not contain `{` or `}`, which OpenCode would replace with a variable or a file's content.
- **`apiKeyEnv`** names the variable holding the key; the key never goes in the file, and only this variable reaches the runtime. Platform tokens and cloud credentials (`GITHUB_`, `GITLAB_`, `CI_`, `AWS_`, `AZURE_` and similar) are refused. Omit it for a server without keys.
- **`effort`** (optional) says how the endpoint takes a [reasoning effort](./configuration#effort), on either runtime: `openai` (default; OpenAI, Gemini's OpenAI-compatible endpoint and OpenRouter accept it) sends `reasoning_effort`, `openrouter` sends `reasoning: { effort }`.
- **`toolCalls`** (optional) says how the endpoint's models call the review tools, on the `direct` runtime: `api` (default) through the protocol's `tools` parameter, `text` for an endpoint that takes none (see [An endpoint without function calling](#an-endpoint-without-function-calling)). The `opencode` runtime refuses `text`.
- **Every model has a price** in US dollars per million tokens: `input`, `output`, optionally `cachedInput`, used for the reported cost and `--max-cost-usd`. A price of 0 (your own hardware) makes the run warn that the spend limit does not count the model.
- **`contextWindow`** (optional, on a model) is the number of tokens one request to it may hold, for a model served with a small window (see [A model with a small context window](#a-model-with-a-small-context-window)).
- A shared configuration (`extends`) may declare providers only when pinned with `#sha256=`; otherwise whoever serves it could redirect your code. ocra ignores an unpinned one that declares providers, with a warning giving the pin to add once you have checked it. The repository's declaration of the same id wins. In pull and merge requests, providers come from the base commit.

Tested in CI against a fake OpenAI-compatible server with the real OpenCode binary (the key goes where it should, the price is counted, nothing else is reached), and live on OpenRouter (a free model, 2026-10-02).

### An endpoint without function calling

A reviewer works by calling tools: it reads files, searches the code, and reports each finding with one. Some servers take no `tools` parameter: vLLM started without `--enable-auto-tool-choice` and `--tool-call-parser`, an Ollama model without a tool template, a company gateway that only forwards messages. On the [`direct` runtime](#choosing-the-runtime) ocra still reviews with them:

- **When the endpoint refuses the tools** (HTTP 400 or 422 naming them), the request is sent again with the tools described in the system prompt. The model writes each call as a `<tool_call>` block holding JSON, the form open models such as Qwen and Hermes are trained on, and gets the results in the next message. The run remembers the model, so only its first requests pay for a refusal.
- **When the endpoint drops the tools without saying so**, the model never sees them, and the review ends as partly reviewed with no tool calls. Declare `"toolCalls": "text"` on the provider and every request goes that way from the start.

```json
{
  "runtime": "direct",
  "providers": {
    "gateway": {
      "type": "openai-compatible",
      "baseUrl": "https://llm.example.com/v1",
      "apiKeyEnv": "GATEWAY_API_KEY",
      "toolCalls": "text",
      "models": { "qwen3-coder": { "input": 0, "output": 0 } }
    }
  }
}
```

The steps, the step cap, the checks on each finding and what a tool may read are the same either way. How well a model keeps to the form is the model's: one that writes a call ocra cannot read is told so and may correct it, and one that never writes a call reviews nothing, which the report says. Where the server can parse tool calls itself, turn that on instead: it is the more reliable of the two.

Tested against a scripted endpoint (a refused `tools` parameter, a declared provider, a malformed call); not yet run against a live model.

### A model with a small context window

ocra sizes a review for the windows of current hosted models: a task's first prompt can reach tens of thousands of tokens, and its conversation grows with every file the reviewer reads. A self-hosted model served at 16K or 32K tokens refuses a request past its window, and the task fails. Declare the window on the model, as the server enforces it, the answer included (vLLM's `--max-model-len`):

```json
"models": { "qwen3-coder": { "input": 0, "output": 0, "contextWindow": 32000 } }
```

- **The plan fits it**, on either runtime: a task's diff is held to a quarter of the smallest window among the models the run names, so a large change becomes more and smaller tasks.
- **A conversation stops before it overflows**, on the [`direct` runtime](#choosing-the-runtime): when the next request would leave less than 15% of the window, the reviewer gets its wrap-up turn to report what it confirmed, and its files count as partly reviewed (`ended: context_window`). The review is then incomplete (exit code 3) and says why.
- **A prompt that does not fit at all** is not sent: the attempt fails on that model, naming both sizes, and the next model of the chain takes the task.

The smallest window ocra accepts is 8,000 tokens. The context around the diff (guidelines, rules, linked tasks, callers) is not cut down for a small window, so under about 32K a reviewer has little room left to read code: serve the model with the largest window the hardware affords. The `opencode` runtime plans with the window but does not stop a conversation at it.

Tested against a scripted endpoint that refuses requests past its window; not yet run against a live model.

### An endpoint that speaks Anthropic's API

Anthropic's own API, or a gateway in its Messages protocol, is declared with `"type": "anthropic"` and runs on the [`direct` runtime](#choosing-the-runtime):

```json
{
  "runtime": "direct",
  "models": {
    "top": "claude/claude-opus-5-5",
    "standard": "claude/claude-sonnet-5-5",
    "light": "claude/claude-haiku-5-5"
  },
  "providers": {
    "claude": {
      "type": "anthropic",
      "baseUrl": "https://api.anthropic.com",
      "apiKeyEnv": "ANTHROPIC_API_KEY",
      "models": {
        "claude-opus-5-5": { "input": 4, "output": 20, "cachedInput": 0.2 },
        "claude-sonnet-5-5": { "input": 2, "output": 10, "cachedInput": 0.1 },
        "claude-haiku-5-5": { "input": 0.1, "output": 0.5, "cachedInput": 0.01 }
      }
    }
  }
}
```

- **`baseUrl`** is the address `/v1/messages` sits under, so it has no `/v1` of its own.
- **The prompt cache is used at every step**: an agent's next request reads the conversation so far at the `cachedInput` price. Input the provider stores is counted at a quarter above `input`, as Anthropic charges it. A call that is one request (Verify, Judge, grouping) stores only its system prompt, which the calls of its kind share: nothing would read the rest again. Review tasks also mark the start of the prompt they share (the change request, the changed files, the guidelines), so each reviewer's later tasks read it instead of storing it again. A plan call is sent as its reviewer, with the task's tools, and stores the prompt up to the end of the files, which the task it prepares then reads.
- **An [effort](./configuration#effort)** goes as `output_config.effort` with adaptive thinking; `minimal` and `none` go as `low`, the API's lowest level. A model that refuses the parameters is asked again without them. `effort` in the declaration does not apply and is refused.
- **`temperature` and `seed` are not sent**: the API takes no seed and its newer models no temperature. The report lists them as not applied.
- The `opencode` runtime refuses such a declaration; it reaches Anthropic as the catalog provider `anthropic/<model>` instead.

Tested against a scripted Messages endpoint (the key goes only where it should, the cache marks, the price, a refused effort). Run live on Anthropic's API through ocra Cloud (`ocra-anthropic/<model>`); a declaration of your own has not been run live yet.

## Free models through OpenRouter

A free model on [OpenRouter](https://openrouter.ai) is declared like any endpoint, at a price of 0 under OpenRouter's model id, and named `<endpoint id>/<model id>`. [`ocra init`](./cli#ocra-init) writes this for an OpenRouter key, with `openrouter/free`, the router that sends each request to one of its free models:

```json
{
  "models": {
    "top": "router/openrouter/free",
    "standard": "router/openrouter/free",
    "light": "router/openrouter/free"
  },
  "providers": {
    "router": {
      "type": "openai-compatible",
      "baseUrl": "https://openrouter.ai/api/v1",
      "apiKeyEnv": "OPENROUTER_API_KEY",
      "models": { "openrouter/free": { "input": 0, "output": 0 } }
    }
  }
}
```

- The run reports a cost of $0 and warns that `--max-cost-usd` does not count the model; tokens are still reported.
- With `--no-repo-config`, as in the evaluation harness, keep the file outside the reviewed repository and pass it with [`--config`](./cli).
- The evaluation's judge can use the same endpoint: `JUDGE_API_KEY`, `JUDGE_BASE_URL=https://openrouter.ai/api/v1` and `JUDGE_MODEL=openrouter/free`.
- The router picks a different model per request, so review quality varies. To compare runs, name one free model (its id ends in `:free`, such as `nvidia/nemotron-3-ultra-550b-a55b:free`, which this repository's CI pins); OpenRouter withdraws free models without notice, and a withdrawn one answers HTTP 404, failing the review.
- Without credits, OpenRouter allows about 50 free requests a day across its `:free` models, and 1000 once the account has bought at least $10 of credits; a review takes 30 to 70 requests per task, so a large one may stop part way. Some zero-price models without `:free` need credits and answer HTTP 402 otherwise.
- Free models, limits and prices change without notice, and a free model's provider may keep what it is sent. Use them to try ocra, not on code you must keep private.

The declared endpoint works without OpenCode's pricing catalog; the catalog form, `openrouter/<model>`, needs the catalog reachable and the model in it, and fails at once otherwise.

## Choosing the runtime

Three runtimes can run the reviewers; `runtime` in the configuration picks one:

| Runtime | Reaches | Use it when |
|---|---|---|
| `opencode` (default) | Every provider in OpenCode's catalog and your declared endpoints, plus the pricing catalog `models.opencode.ai` | Your models are Gemini, Vertex AI, Anthropic, Bedrock or another catalog provider |
| `direct` | Only the endpoints declared under `providers`, in OpenAI's or Anthropic's protocol; nothing else on the network | Every model in your chains is on a declared endpoint, and you want nothing but that endpoint reached |
| `codex` (new) | OpenAI, through the [Codex CLI](https://github.com/openai/codex) signed in on your computer | You review on your own ChatGPT plan rather than an API key |

Both run the same review: tools, step cap, failback and prices. `direct` refuses, before any request, a chain naming a provider you did not declare, and honors `HTTP_PROXY`, `HTTPS_PROXY` and `NO_PROXY`. The [quality numbers](./quality) were measured on `opencode`; `direct` passes the same conformance tests but has not been evaluated on the golden set yet.

To see what `direct` sent a model and got back, set `OCRA_RECORD_DIR` to a directory: each request is written there as a JSON file with its answers, readable only by you. Keys become `<key>`, an ocra Cloud token renewed during the run included, and headers and the endpoint address are left out, but the files hold the code and prompts, so guard them like the code. A recording ocra cannot write is a warning on stderr; the review goes on and no request is sent again. A recording replays only the exact conversation it recorded. `opencode` ignores the variable.

`codex` runs each reviewer as one `codex exec` on the Codex signed in on your computer (`codex login`; Codex 0.172.0 or later, found as `codex` on `PATH` or at `OCRA_CODEX_BIN`). Its chains name `codex/default`, Codex's own default model, or `codex/<model>` with a model your Codex offers; any other provider is refused before Codex starts. The reviewer reads the change only through ocra's tools: Codex's shell, file, web and plugin tools are switched off, it runs in an empty directory, read-only, without your `config.toml`, rules or MCP servers, and the review is not kept among your Codex sessions. An API key in the environment is not passed to it. Tokens are reported and cost $0, since your plan pays; a spent usage limit drops the model for the run. A review that is not finished at the step cap ends there: Codex keeps no session to give it the wrap-up turn.

The `opencode` runtime is an optional dependency, installed by default; with `direct` you can leave it out and save about 165 MB: see [Without OpenCode](./installation#without-opencode) and the Action's `opencode: false` [input](./github#the-runtime).

## What else reaches the network

Besides the model providers, OpenCode fetches its pricing catalog from `models.opencode.ai` at start. Its attempts to install its plugin package, or a provider's code, from npm go to a local registry that refuses them at once. A review works with every address but a declared endpoint refused (tested): the catalog fetch fails, OpenCode uses its bundled catalog, and a model missing from it has no price, so the run warns its calls are not counted.
