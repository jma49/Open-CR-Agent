title: 威胁模型
description: 恶意 PR 能尝试什么、由什么挡住，以及 ocra 不防什么。
---

ocra 的设计目标是审查陌生人提交的 PR。本页列出这样的 PR 能尝试什么、由什么挡住、哪些风险仍由你承担；各项机制见[安全与隐私](./security)。

本页适用于 GitHub Action 和 `ocra review --pr`、`ocra review --mr`，以及带 `--no-repo-config` 的本地审查。普通的本地审查会信任代码目录里的 `.ocra/config.json`，包括其中的插件：审查不信任的代码时请加上 `--no-repo-config`。

## 保护什么

- **你的密钥：**模型 key、GitHub token，以及不在被审查版本里或看起来像密钥的任何文件。
- **你的 runner 或机器：**ocra 不会执行 PR 里的任何东西。
- **你的仓库：**ocra 只发布审查评论，配置了时请求或撤回修改，不写入其他东西。
- **ocra 发布的内容：**PR 无法让 ocra 的评论隐藏链接的真实目标、显示图片、@ 提及他人、夹带隐藏标记或下达命令。
- **你的花费：**每个调用模型的循环都有上限。

不承诺：结论正确。模型会读到 PR 的内容，所以可能被诱导，也可能出错。

## 谁会发起攻击

| 谁 | 能控制什么 |
|---|---|
| PR 的作者（来自 fork 或分支） | diff 和 head 上的每个文件（包括 `.ocra/`、`.opencode/` 和 `AGENTS.md`）、文件名、提交信息、标题和描述 |
| 任何能发表评论的人 | PR 上的回复和评审意见 |
| 对你的仓库有推送权限的人（在 GitLab 上是 Developer 角色） | 上面的全部，以及他们的分支所运行的流水线：GitHub 上他们推送的任何 workflow，GitLab 上 Merge Request 的 `.gitlab-ci.yml`（见[谁掌控流水线](#谁掌控流水线)） |
| 模型供应商 | ocra 发给它的全部内容（[发送了什么](./security#会发送给模型供应商的内容)） |
| 被攻破的软件包或 registry 账号 | ocra 安装的代码 |

## 攻击方式与防护

| PR 试图 | 由什么挡住 |
|---|---|
| 执行代码：`.ocra/config.json` 里的插件、`.opencode/` 里的 OpenCode 插件或工具、安装脚本、git 驱动 | 配置、规则、记忆和 `AGENTS.md` 从 base 提交读取；审查 PR 时从不加载仓库插件；OpenCode 的项目配置被关闭。ocra 从不检出、安装或构建 PR，git 读取它时关闭了外部 diff 驱动和文本转换。 |
| 借审查员读取密钥 | 审查员只能读取被审查的版本，限于仓库之内，不跟随链接，读不到疑似密钥文件和 `.git/`（[隔离](./security#隔离)）。OpenCode 进程只拿到系统基础变量和模型供应商的凭据（以及你在 `OCRA_RUNTIME_ENV` 里列出的变量），从不包括 `GITHUB_TOKEN` 或其他 CI 变量。 |
| 让密钥出现在 ocra 的评论里 | 密钥从不进入提示词，所以没有模型能复述它。 |
| 藏起问题，或说服 Judge 丢掉问题（提示词注入） | 一切都作为数据交给模型，冒充 ocra 自己分段的文字会被改写（[不可信的输入](./security#不可信的输入)）。只有经核查确认的 critical 能阻止合并，Judge 既不能丢掉也不能降级它们。这限制了诱导，但不能阻止。 |
| 伪造命令或驳回 | 只有作者以外、有写权限的人才算数，被别人编辑过的评论不算。override 必须写出完整的 head 提交 id。讨论串只有在其中 ocra 的评论没被别人编辑过时才算数，所以无法换掉它指向的问题。 |
| 在 ocra 的评论里埋入标记或链接 | 模型文字无法闭合 ocra 的标记、嵌入图片或 HTML、@ 提及他人（通过 `&#64;` 这样的字符引用也不行）、写出 ocra 的命令、以斜杠开头一行（GitLab 的快捷操作，比如 `/merge`），也无法变成链接：任何协议的地址都显示为纯文字。引用的代码（反引号围栏或行内代码）原样发出，因为代码段里这些都不会被渲染；不成对的反引号会被转义，无法在评论后面开启代码段。 |
| 篡改 ocra 在汇总评论里保存的状态 | 只有评论由 ocra 的账号发布、最后一次编辑也来自它时，状态才算数；状态会被校验，大小有上限。 |
| 改写你的终端（本地运行） | 所有输出（包括 JSON）里的控制字符、转义序列和双向文本控制符都会被替换。 |
| 把提交进来的会话文件冒充成一次早先的审查（`--resume`，本地运行） | 只复用用你自己的密钥封存过的会话行，密钥存放在所有仓库之外；没有这些行的会话会被拒绝（[会话记录](./cli#会话记录)）。 |
| 刷高你的模型账单 | 每个任务 30 步、每次运行 60 个任务、有上限的文件读取和工具返回、每个任务最多 50 条问题，以及每次运行的 `--max-cost-usd`。在 CI 里还要限制谁能触发审查（[来自 fork 的 PR](./github#来自-fork-的-pr)）。 |

这些防护都有测试，和对应的代码放在一起，见[代码仓库](https://github.com/jma49/Open-CR-Agent)。

## 谁掌控流水线

ocra 针对作者的规则（不能驳回、不能放行、不能伪造之前的审查）只有在作者既改不了运行 ocra 的任务、也读不到它的 secret 时才成立。

**GitHub。**来自 fork 的 PR 在 `pull_request` 下拿不到 secret，在 `pull_request_target` 下 workflow 来自你的默认分支：两种情况下审查都不在作者手里。但有推送权限的人推送的 workflow 会拿到仓库的 secret，以及以 ocra 默认信任的 `github-actions[bot]` 身份发言的 `GITHUB_TOKEN`，所以他们可以读到模型密钥或伪造 ocra 的摘要。[GitHub Pull Request](./github#自己的开发者也改不了的审查) 给出了防止这两点的配置：`pull_request_target`、secret 放在只有默认分支能用的环境（environment）里、评论由 ocra 改为信任的 GitHub App 发出、`.github/workflows` 需要代码负责人审查。

**GitLab。**来自 fork 的 Merge Request 在 fork 里运行流水线，拿不到你的变量。来自你项目分支的 Merge Request 运行作者写的流水线，每个任务都能读到项目未受保护的变量：它的审查只是作者可以伪造的建议（[GitLab Merge Request](./gitlab#谁掌控流水线)）。流水线执行策略（GitLab Ultimate）保护得了任务，保护不了令牌。

一个尚未试过的设计：一个只有维护者能改的单独审查项目，由 Merge Request 的 webhook 通过流水线触发器启动，在它受保护的默认分支上运行，令牌和模型密钥是受保护的变量，把 Merge Request 当作数据读取。开发者既改不了审查，也读不到它的 secret。它的结果不是 Merge Request 流水线的状态，所以合并仍要靠审批规则把关。

## ocra Cloud

本节只在你已登录（`ocra login`）且 `OCRA_CLOUD` 不是 `off` 时适用；未登录的审查从不连接 ocra Cloud。它保存什么、保存多久，见[数据政策](https://app.ocracloud.com/privacy)；相关决定是 ADR-0024、ADR-0027 和 ADR-0028。

| 谁 | 能控制什么 |
|---|---|
| ocra Cloud，或攻破了它的人 | CLI 拉取的你账号的设置、规则、插件名称和 memory；带着你存的 key 经过网关的 `ocra-<provider>/<model>` 模型调用；CLI 发送的统计数据和共享的问题 |
| 拿到你终端会话令牌的人 | 用你存的 key 通过网关调用模型，受账号每日上限约束 |
| 拿到你浏览器会话的人 | 你的设置、规则、插件名称和 memory，以及替换或删除你存的 key |

| 他们试图 | 什么阻止它 |
|---|---|
| 把你的代码或本机 key 发到他们指定的服务器 | 无论服务器发什么，CLI 都会丢弃账号设置里的 provider、`extends` 和 key 的环境变量。账号模型必须是 `ocra-<provider>/<model>`，只能到达网关固定列表中的服务商。 |
| 在你的机器上执行代码 | 账号列出的插件，只有你在本机安装并允许了那个确切版本（`ocra plugins allow`）时才加载，只从该目录加载，加载前校验完整性；`--pr`、`--mr` 审查和 `--no-repo-config` 时从不加载。未知的运行时名称会被丢弃。 |
| 读取你存的服务商 key | key 用与数据库分开保存的主密钥加密，从不返回给终端或浏览器会话。 |
| 通过设置和规则削弱审查或抬高费用 | 仓库配置（包括费用上限）优先于账号设置；网关每日上限和你在服务商处的上限约束费用。`ocra review --plan` 显示每项设置的来源，报告记录设置版本和每条规则的来源，网页保留每次保存的版本。 |
| 通过 memory 隐藏问题 | 账号 memory 只作用于它的仓库，且只在登录时生效；终端、报告和 PR 摘要会写明它隐藏了几个问题，与 `.ocra/memory.json` 分开计数。 |
| 读取你的代码 | 只有你经网关路由的调用（`ocra-` 模型）会在内存中经过它；它保存统计数据，只有你开启共享后才保存问题及其引用的代码，且先在你的机器上对疑似密钥脱敏。仓库以加盐哈希发送。 |

被盗的终端会话不能修改设置、读取 key；在网页的会话页撤销它，刷新令牌立即失效。登录状态下审查不可信的 PR，仍然使用基准提交的配置，账号设置和 memory 叠在其下，且不加载任何账号插件。

## ocra 不防什么

- **诱导。**干净的结论什么也证明不了（[原因](./security#结论不是安全门禁)）。
- **模型供应商。**它能看到被审查的代码；请选择你能接受其数据政策的供应商。
- **ocra 及其依赖本身的缺陷。**ocra、OpenCode、git 和 Node.js 都会处理 PR，其中的漏洞会在你的模型 key 和 token 在场时被利用。请限制它能触及的范围：只用于审查、设了花费上限的模型 key，以及示例里的 token 权限。
- **你自己的 workflow。**在拿得到 secret 的 job 里检出并安装、构建或测试 PR，以上所有防护都会失效。
- **推送权限，**除非按[上面](#谁掌控流水线)的方式配置流水线。
- **供应链。**Action 安装已发布的 ocra，依赖按 lockfile 固定，关闭安装脚本，校验 registry 签名（[GitHub Action](./github#github-action)）；ocra 的包带 provenance，OpenCode 版本固定、内置工具由测试核对。被盗的 npm 账号仍可能发布有问题的版本，使用安全密钥的双重验证让这很难做到。请按提交固定 Action。
