**Open-CR-Agent**（`ocra`）用一条流水线审查代码改动：确定性的工程步骤包裹着少量大模型 agent。不能出错的事交给代码（审哪些文件、怎么分组、评论落在哪一行），需要判断的事交给模型。

## 为什么选择 ocra

- **精确优先。** 每个审查员都明确写了"不该报什么"，没通过校验的问题不会出现在你面前。一次安静但可信的审查，胜过一次吵闹却只能扫一眼的审查。
- **评论落在正确的行上。** 模型只引用它所指的代码，由 ocra 自己解析出准确行号，模型从不编造行号。
- **一切皆插件。** 代码托管平台、agent 运行时、审查员、规则包、工具和事件监听都是插件。
- **任意模型，自动降级。** 每个层级可以配置一串模型，遇到过载或额度用完会自动切到下一个。
- **成本透明。** 每次运行都会报告输入、输出、推理和缓存 token，以及每次尝试的花费。
- **靠数据说话。** 改动会在 [AACR-Bench](./evaluation) 基准上评测。

## 当前状态

ocra 还处于早期开发阶段。

| 里程碑 | 范围 | 状态 |
|---|---|---|
| M1 | 本地 CLI、文件选择、分组、行号定位、correctness 审查员、OpenCode 运行时、插件、评测 | 已完成 |
| M2 | 专项审查员、审查矩阵、逐条核查与最终裁决、风险分档 | 下一步 |
| M3 | GitHub App / Action，支持行内评论和增量复审 | 规划中 |
| M4 | 熔断器、远程配置、长期审查记忆、`--ultra` 模式 | 规划中 |
