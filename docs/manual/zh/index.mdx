title: 简介
description: ocra 是一个专为不可信 PR 设计的开源 AI 代码审查工具，问题站不住脚就不开口。
---

**ocra** 审查本地改动、GitHub Pull Request 和 GitLab Merge Request，用你自己的模型 key 在你的 CI 里运行。它假定所审的改动可能出自攻击者之手；一条问题只有引用了它所指的代码、并经得起第二遍核查，才会被说出来，否则它保持安静。

## 为什么选择 ocra

- **恶意 PR 是设计的出发点。** agent 只有只读工具、没有 shell，不可信的文本始终只是数据；审查 PR 时，被审代码树里的任何东西都不会运行。见[安全](/zh/docs/security)。
- **评论之前先过第二遍。** 核查员丢掉被代码证伪的问题，Judge 合并重复，结论由代码算出。每个审查员也都明确写了"不该报什么"。
- **按审查方向、也按文件分组。** correctness、security、performance、docs 和 `AGENTS.md` 审查员各自作为隔离任务审查一组相关文件，由带测试的规划器决定哪个审查员读哪一组。
- **问题跟着代码走。** 模型引用代码，由 ocra 解析出行号，所以行号不会是编造的。下一次 push 时，只有问题所指的代码不在了才算已修复，也只有维护者能驳回它。
- **任意模型，自动降级，账单有上限。** 每个层级是一串模型，遇到过载会切到下一个。花费上限一到就不再启动新任务，每次运行都报告 token 和每次尝试的花费。
- **靠数据说话。** ocra 在自己的黄金用例和 AACR-Bench 基准上接受评测，[结果](/zh/docs/quality)连同局限一起公开。

## 当前状态

ocra 目前是早期的 0.x 版本。CLI 参数、配置项、退出码和报告格式是[约定](/zh/docs/stability)，只会在预先告知后改变；提示词和审查质量仍在变动。
