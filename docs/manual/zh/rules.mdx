审查员会结合三层指引。

## 内置规则

正确性审查员会拿到通用正确性规则（逻辑错误、调用双方不一致的契约、被掩盖的失败、资源与并发问题、数据完整性，以及改动中可见的安全缺陷），并根据分组里的文件加入对应的语言规则；安全和性能审查员则使用各自的规则集：

| 语言 | 扩展名 |
|---|---|
| TypeScript / JavaScript | `.ts` `.tsx` `.mts` `.cts` `.js` `.jsx` `.mjs` `.cjs` |
| Python | `.py` `.pyi` |
| Go | `.go` |
| Java | `.java` |

每个审查员的提示词里还列出了**不该报**的内容：代码风格和格式、拿不出可触发输入的推测、缺少测试或文档、重构建议，以及本次改动没有涉及的代码里的问题。

## AGENTS.md

仓库根目录的 `AGENTS.md` 会作为仓库规范交给审查员，超过 20,000 个字符的部分被截断。它读取被审查的版本（审查 PR 时读 base 提交，PR 无法改写它）。适合写要执行的约定：架构边界、错误处理规范、禁用的 API。

## .ocra/rules.json

按路径生效的规则，只有分组里包含匹配的文件时才会生效：

```json
{
  "rules": [
    {
      "path": "services/billing/**",
      "rule": "Every write must carry an idempotency key. Flag handlers that retry without one."
    },
    {
      "path": ["**/*.sql", "db/migrations/**"],
      "rule": "Migrations must be backward compatible with the previous release."
    }
  ]
}
```

- `path`：一个 glob，或一组 glob。
- `rule`：交给审查员的规则文本。

`rules.json` 不合法时审查会报错停止。审查 PR 时从 base 提交读取。

## 来自插件的规则

插件也可以提供规则，比如公司统一的规则包。详见[插件](./plugins)。
