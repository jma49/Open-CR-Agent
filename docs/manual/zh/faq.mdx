## 为什么 ocra 报出的问题这么少？

这是有意为之。ocra 精确优先：审查员被明确告知哪些内容不该报，问题要经过校验，不属于本任务文件的问题会被丢弃以避免重复。对正确的改动给出空报告，本来就是好结果。

## 一次审查要花多少钱？

取决于模型和改动大小。每次运行都会打印每次尝试和总计的 token 与花费。作为参考，一个 2 个文件、32 行的 commit，用 `gemini-flash-lite-latest` 花费 $0.006。把相关文件分组审查，加上每个 agent 最多 20 步，都能把成本控制住。

## 可以用哪些模型？

OpenCode 支持的所有模型，写成 `provider/model`。建议每个层级都配置降级链，这样某个模型过载时审查也不会失败。

## 支持 GitHub PR 吗？

还不支持。目前 ocra 审查本地改动；带行内评论的 GitHub 集成规划在 M3。

## 为什么不让模型直接给行号？

模型经常把行号写错，所以让它引用代码，再由 ocra 解析出行号。详见[工作原理](./how-it-works#行号定位)。

## 结果保存在哪里？

每次运行都会在被审查的仓库里写入 `.ocra/sessions/<id>/events.jsonl` 和 `report.json`。
