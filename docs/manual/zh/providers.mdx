在默认运行时上，OpenCode 目录里的供应商都可以用，只有少数[需要从 npm 下载代码的](#需要从-npm-下载代码的供应商)除外。在模型链里把模型写成 `provider/model`（见[配置](./configuration#模型)）；运行时只拿到链里出现的供应商的凭据。

## OpenCode 目录中的供应商

| 供应商 | 模型示例 | 需要设置 | 实测过 |
|---|---|---|---|
| Gemini API | `google/gemini-3.5-flash` | `GEMINI_API_KEY`（或 `GOOGLE_API_KEY`、`GOOGLE_GENERATIVE_AI_API_KEY`） | 是 |
| Vertex AI | `google-vertex/gemini-3.5-flash` | `GOOGLE_VERTEX_PROJECT`、`GOOGLE_VERTEX_LOCATION=global`，以及应用默认凭据或 `GOOGLE_APPLICATION_CREDENTIALS` | 是，也包括在 GitHub Actions 里通过工作负载身份联合免密钥使用 |
| Anthropic | `anthropic/<model>` | `ANTHROPIC_API_KEY` | 否 |
| OpenAI | `openai/<model>` | `OPENAI_API_KEY` | 否 |
| Amazon Bedrock | `amazon-bedrock/<model>` | `AWS_REGION` 和 AWS 凭据：`AWS_ACCESS_KEY_ID` 与 `AWS_SECRET_ACCESS_KEY`（加上 `AWS_SESSION_TOKEN`）、`AWS_PROFILE`，或 `AWS_BEARER_TOKEN_BEDROCK` | 否 |
| Azure OpenAI | `azure/<deployment>` | `AZURE_API_KEY`、`AZURE_RESOURCE_NAME` | 否 |
| DeepSeek、OpenRouter、Groq、Mistral、xAI 以及目录里的其他供应商 | `deepseek/<model>` | 供应商的密钥，比如 `DEEPSEEK_API_KEY`；ocra 不认识的 id 会拿到以它开头的所有变量，比如 `GROQ_` | 否 |

"否"：ocra 传入变量，其余由 OpenCode 处理，但还没有审查实际经过这个供应商运行过；出了问题请[提 issue](https://github.com/ocrahq/Open-CR-Agent/issues/new/choose)。模型 id 以 OpenCode 的目录 [models.dev](https://models.dev) 为准。

### 需要从 npm 下载代码的供应商

有少数供应商，OpenCode 会在第一次使用时从 npm 下载其客户端代码，而 ocra 不允许审查过程中下载。在 2026-09-29 的目录里，它们是 `aihubmix`、`cloudflare-ai-gateway`、`merge-gateway`、`qvac`、`salad-cloud`、`sap-ai-core` 和 `watsonx`；它们的模型会立即失败，报错 "Failed to initialize provider"。如果这类服务有 OpenAI 兼容端点，可以声明为[你自己的端点](#你自己的端点)。

## 你自己的端点

自建的服务（vLLM、Ollama、LM Studio）或者兼容 OpenAI API 的公司网关，在 `.ocra/config.json` 里声明：

```json
{
  "models": {
    "standard": "gateway/qwen3-coder",
    "light": "gateway/qwen3-small",
    "top": "gateway/qwen3-max"
  },
  "providers": {
    "gateway": {
      "type": "openai-compatible",
      "baseUrl": "https://llm.example.com/v1",
      "apiKeyEnv": "GATEWAY_API_KEY",
      "models": {
        "qwen3-coder": { "input": 0.5, "output": 2, "cachedInput": 0.1 },
        "qwen3-small": { "input": 0.1, "output": 0.4 },
        "qwen3-max": { "input": 2, "output": 8 }
      }
    }
  }
}
```

- **id**（`gateway`）由你自己取：小写字母、数字和连字符。避开 OpenCode 目录里已有的 id：声明会在这次运行中替换同名的已知供应商。
- **`baseUrl`** 必须是 `https`，或者本机上的普通 `http`：`localhost`、`127.0.0.1` 或 `::1`。比如 Ollama 用 `http://127.0.0.1:11434/v1`。地址里不能有 `{` 或 `}`，OpenCode 会把它们替换成变量或文件内容。
- **`apiKeyEnv`** 是保存密钥的变量名；密钥从不写进文件，运行时也只拿到这一个变量。平台令牌和云凭据（`GITHUB_`、`GITLAB_`、`CI_`、`AWS_`、`AZURE_` 等）会被拒绝。不需要密钥的服务可以省略。
- **`effort`**（可选）说明端点怎样接收 `opencode` 或 `direct` 发送的[推理强度](./configuration#推理强度)：`openai`（默认；OpenAI、Gemini 的 OpenAI 兼容端点和 OpenRouter 都接受）发送 `reasoning_effort`，`openrouter` 发送 `reasoning: { effort }`。
- **`toolCalls`**（可选）说明端点上的模型在 `direct` 运行时下怎样调用评审工具：`api`（默认）通过协议的 `tools` 参数，`text` 用于不接受该参数的端点（见[不支持函数调用的端点](#不支持函数调用的端点)）。`opencode` 运行时拒绝 `text`。
- **每个模型都要有价格**，单位是每百万 token 美元：`input`、`output`，可选 `cachedInput`，用于报告的花费和 `--max-cost-usd`。价格为 0（你自己的硬件）时，运行会警告花费上限不计入这个模型。
- **`contextWindow`**（可选，写在模型上）是一次请求最多能容纳的 token 数，用于上下文窗口较小的模型（见[上下文窗口较小的模型](#上下文窗口较小的模型)）。
- 共享配置（`extends`）只有用 `#sha256=` 固定后才能声明供应商，否则提供文件的人就能把你的代码转到别处。声明了供应商却没固定的共享文件会被忽略，警告里给出检查后要加的固定值。仓库里同 id 的声明优先。审查 PR 和 Merge Request 时，供应商来自 base 提交。

已在 CI 里用真实的 OpenCode 二进制文件对模拟的 OpenAI 兼容服务测试过（密钥发往该去的地方，价格被计入，不访问其他地址），也在 OpenRouter 上真实运行过（一个免费模型，2026-10-02）。

### 不支持函数调用的端点

评审者靠调用工具工作：读文件、搜索代码，每条发现也用一个工具上报。有些服务不接受 `tools` 参数：启动时没带 `--enable-auto-tool-choice` 和 `--tool-call-parser` 的 vLLM、没有工具模板的 Ollama 模型、只转发消息的公司网关。在 [`direct` 运行时](#选择运行时)上，ocra 仍然能用它们评审：

- **端点拒绝工具时**（HTTP 400 或 422，且错误里提到工具），请求会重发一次，工具改在系统提示词里描述。模型把每次调用写成一个包含 JSON 的 `<tool_call>` 块，这是 Qwen、Hermes 等开源模型训练时用的格式，结果在下一条消息里返回。本次运行会记住这个模型，所以只有它最初的几个请求会被拒绝一次。
- **端点悄悄丢掉工具时**，模型根本看不到工具，评审会以“部分评审、没有工具调用”结束。在该供应商上声明 `"toolCalls": "text"`，每个请求从一开始就走文本方式。

```json
{
  "runtime": "direct",
  "providers": {
    "gateway": {
      "type": "openai-compatible",
      "baseUrl": "https://llm.example.com/v1",
      "apiKeyEnv": "GATEWAY_API_KEY",
      "toolCalls": "text",
      "models": { "qwen3-coder": { "input": 0, "output": 0 } }
    }
  }
}
```

两种方式下，步骤、步数上限、对每条发现的检查以及工具能读到的内容都一样。模型能不能守住这个格式取决于模型本身：写出 ocra 读不懂的调用时，ocra 会告诉它，它可以改正；始终不写调用的模型什么也评审不了，报告会如实说明。如果服务端自己能解析工具调用，优先打开它：那是两者中更可靠的一种。

已在脚本化端点上测试（被拒绝的 `tools` 参数、声明了的供应商、格式错误的调用）；尚未在真实模型上运行。

### 上下文窗口较小的模型

ocra 按当前托管模型的窗口来安排评审：一个任务的首个提示词可达数万 token，评审者每读一个文件，对话还会变长。以 16K 或 32K token 部署的自托管模型会拒绝超出窗口的请求，任务随之失败。请在模型上声明窗口，数值以服务器实际执行的为准，包含回答在内（vLLM 的 `--max-model-len`）：

```json
"models": { "qwen3-coder": { "input": 0, "output": 0, "contextWindow": 32000 } }
```

- **计划按窗口安排**，适用于 `opencode` 和 `direct`：一个任务的 diff 不超过本次运行所用模型中最小窗口的四分之一，因此大的改动会拆成更多、更小的任务。
- **对话在溢出之前停下**，仅限 [`direct` 运行时](#选择运行时)：下一次请求会让窗口剩余不足 15% 时，评审者进入收尾轮，报告已确认的问题，它的文件记为只审查了一部分（`ended: context_window`）。这次评审即为不完整（退出码 3），并说明原因。
- **完全放不下的提示词**不会发送：这次尝试在该模型上失败，并给出两个大小，任务交给模型链中的下一个模型。

ocra 接受的最小窗口是 8,000 token。diff 之外的上下文（规范、规则、关联任务、调用方）不会因窗口小而缩减，所以窗口低于约 32K 时，评审者几乎没有余量读代码：请按硬件允许的最大窗口部署模型。`opencode` 运行时按窗口做计划，但不会在窗口处停下对话。

已针对一个拒绝超窗口请求的脚本端点测试；尚未在真实模型上运行。

### 使用 Anthropic API 的端点

Anthropic 官方 API，或者使用其 Messages 协议的网关，用 `"type": "anthropic"` 声明，并在 [`direct` 运行时](#选择运行时)上运行：

```json
{
  "runtime": "direct",
  "models": {
    "top": "claude/claude-opus-5-5",
    "standard": "claude/claude-sonnet-5-5",
    "light": "claude/claude-haiku-5-5"
  },
  "providers": {
    "claude": {
      "type": "anthropic",
      "baseUrl": "https://api.anthropic.com",
      "apiKeyEnv": "ANTHROPIC_API_KEY",
      "models": {
        "claude-opus-5-5": { "input": 4, "output": 20, "cachedInput": 0.2 },
        "claude-sonnet-5-5": { "input": 2, "output": 10, "cachedInput": 0.1 },
        "claude-haiku-5-5": { "input": 0.1, "output": 0.5, "cachedInput": 0.01 }
      }
    }
  }
}
```

- **`baseUrl`** 是 `/v1/messages` 所在的地址，本身不带 `/v1`。
- **每一步都使用提示缓存**：代理的下一次请求按 `cachedInput` 的价格读取此前的对话。供应商写入缓存的输入按 `input` 加四分之一计费，与 Anthropic 的收费一致。只有一次请求的调用（Verify、Judge、分组）只缓存系统提示词，同类调用共用它：其余内容不会再被读取。审查任务还会标出它们共用的提示词开头（变更说明、改动文件列表、规范），同一审查者之后的任务直接读取它，不再重复写入缓存。计划调用以审查者的身份发出，带着任务的工具，并把提示词缓存到文件部分结束处，随后它所准备的任务直接读取。
- **[推理强度](./configuration#推理强度)**以 `output_config.effort` 加自适应思考发送；`minimal` 和 `none` 按该 API 的最低档 `low` 发送。模型拒绝这些参数时，会不带它们重发一次。声明里的 `effort` 不适用，写了会被拒绝。
- **不发送 `temperature` 和 `seed`**：该 API 没有 seed，新模型也不接受 temperature。报告里会把它们列为未生效。
- `opencode` 运行时拒绝这样的声明；它通过目录里的供应商 `anthropic/<model>` 访问 Anthropic。

已对模拟的 Messages 端点测试过（密钥只发往该去的地方、缓存标记、价格、被拒绝的推理强度）。已经通过 ocra Cloud（`ocra-anthropic/<model>`）在 Anthropic 的 API 上真实运行过；你自己声明的端点还没有真实运行过。

## OpenRouter 上的免费模型

[OpenRouter](https://openrouter.ai) 上的免费模型和任何端点一样声明：按 OpenRouter 的模型 id 写，价格为 0，以 `<端点 id>/<模型 id>` 引用。对 OpenRouter 的 key，[`ocra init`](./cli#ocra-init) 写的就是这样的配置，模型是 `openrouter/free`，即把每次请求交给某个免费模型的路由：

```json
{
  "models": {
    "top": "router/openrouter/free",
    "standard": "router/openrouter/free",
    "light": "router/openrouter/free"
  },
  "providers": {
    "router": {
      "type": "openai-compatible",
      "baseUrl": "https://openrouter.ai/api/v1",
      "apiKeyEnv": "OPENROUTER_API_KEY",
      "models": { "openrouter/free": { "input": 0, "output": 0 } }
    }
  }
}
```

- 运行报告的花费是 $0，并警告 `--max-cost-usd` 不计入这个模型；token 数照常报告。
- 带 `--no-repo-config` 运行时（评测工具就是这样），把文件放在被审查仓库之外，用 [`--config`](./cli) 传入。
- 评测的判定模型也可以用同一个端点：`JUDGE_API_KEY`、`JUDGE_BASE_URL=https://openrouter.ai/api/v1`、`JUDGE_MODEL=openrouter/free`。
- 路由每次请求可能选不同的模型，审查质量随之变化。要让运行可比，就指定一个免费模型（id 以 `:free` 结尾，例如本仓库 CI 固定使用的 `nvidia/nemotron-3-ultra-550b-a55b:free`）；OpenRouter 会不经通知下架免费模型，下架的模型返回 HTTP 404，审查失败。
- 没有充值时，OpenRouter 每天约给 50 次免费请求，由各 `:free` 模型共用；账号买过至少 10 美元额度后为每天 1000 次；一个审查任务要 30 到 70 次请求，所以大的审查可能中途停下。有些不带 `:free` 的零价格模型需要充值，否则返回 HTTP 402。
- 免费模型、限额和价格随时可能变，其提供方也可能保留发给它的内容。拿它们试用 ocra，别用于必须保密的代码。

声明端点不需要 OpenCode 的价格目录；目录形式的 `openrouter/<模型>` 需要能访问目录且模型在目录里，否则立刻失败。

## 选择运行时

有三个运行时可以运行审查员，由配置里的 `runtime` 选择：

| 运行时 | 会访问 | 适用场景 |
|---|---|---|
| `opencode`（默认） | OpenCode 目录里的所有供应商和你声明的端点，外加价格目录 `models.opencode.ai` | 你的模型是 Gemini、Vertex AI、Anthropic、Bedrock 或目录里的其他供应商 |
| `direct` | 只访问 `providers` 下声明的端点（OpenAI 或 Anthropic 协议），不访问网络上的其他任何地址 | 模型链里的每个模型都在声明的端点上，而且你希望除此之外什么都不访问 |
| `codex`（0.27.0 及以上） | 通过你电脑上已登录的 [Codex CLI](https://github.com/openai/codex) 访问 OpenAI | 你想用自己的 [ChatGPT 套餐在本地审查](./installation#使用-codex)，而不是 API key |

三个运行时共用同一套审查流水线。两个基于 key 的运行时共用审查工具、步数上限和失败切换的一致性测试。`direct` 会在发出任何请求前拒绝写了未声明供应商的模型链，并读取 `HTTP_PROXY`、`HTTPS_PROXY` 和 `NO_PROXY`。[质量数字](./quality)只在 `opencode` 上测得。

想看 `direct` 给模型发了什么、收到了什么，把 `OCRA_RECORD_DIR` 设成一个目录：每个请求连同回答写成一个 JSON 文件，只有你能读。密钥替换成 `<key>`（运行中续期的 ocra Cloud 令牌也一样），请求头和端点地址不写入，但文件里有代码和提示词，要像代码本身一样保护。写不进记录时会在 stderr 上警告，审查照常继续，不会重发请求。一份记录只能回放它记录的那段对话。`opencode` 不读这个变量。

`codex` 把每个审查员作为一次 `codex exec`，跑在你电脑上已登录的 Codex 上（`codex login`；需要 Codex 0.172.0 或更新，在 `PATH` 上的 `codex` 或 `OCRA_CODEX_BIN` 指定的路径）。它的模型链写 `codex/default`（Codex 自己的默认模型）或 `codex/<model>`（你的 Codex 提供的模型）；其他供应商会在启动 Codex 前被拒绝。审查员只能通过 ocra 的工具读取改动：Codex 的 shell、文件、网页和插件工具都关闭，它在一个空目录里只读运行，不读你的 `config.toml`、规则和 MCP 服务器，审查也不会留在你的 Codex 会话列表里。环境里的 API key 不会传给它。会报告 token 数，费用记为 $0，因为由你的套餐支付；用量额度用完时，这个模型在本次运行中被停用。到步数上限还没完成的审查就此结束：Codex 不保留会话，没法再给它收尾的一轮。

`opencode` 运行时是可选依赖，默认安装；使用 `direct` 时可以不装，少约 165 MB：见[不装 OpenCode](./installation#不装-opencode)和 Action 的 `opencode: false` [输入](./github#运行时)。

## 还会访问哪些网络地址

除模型供应商外，OpenCode 启动时会从 `models.opencode.ai` 拉取价格目录。它从 npm 安装自身插件包或供应商代码的尝试，都被指向本机一个立即拒绝的 registry。除声明的端点外所有地址都被拒绝时，审查依然正常（已测试）：价格目录拉取失败，OpenCode 用自带的目录，不在其中的模型没有价格，运行会警告它的调用没有计入。
