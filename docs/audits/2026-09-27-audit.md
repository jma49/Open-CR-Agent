# Audit, 2026-09-27

A second full audit of Open-CR-Agent (`main` at `b58993d`, 360 tests green), a day after the [self-audit](2026-09-26-self-audit.md) and the [M2–M4 security review](2026-09-26-m2-m4-security.md). It was prompted by a finding while working on #76: commit `07052b6` claimed that the sessions directory carries a `.gitignore`, updated the manual, the pitfalls and a test, and changed no code; the test passed because `git status --porcelain` collapses a new untracked directory to `.ocra/`. That was fixed in #102. This audit looks for more of the same (claims without code, tests that cannot fail) and for new issues in code added since.

Method: four independent reviews in parallel (security; core pipeline correctness; GitHub, CLI, reliability and performance; documentation against code and architecture), no model calls. Findings rated P0 or P1 were confirmed by a repro test or script, by an existing test, or by reading the code, as noted. The repros lived in a scratch directory and are not committed; the issues describe how to reproduce each finding.

Severity: **P0** exploitable or wrong in normal use · **P1** real weakness under realistic conditions · **P2** hygiene.

## Did the earlier fixes land?

Every fix claimed by the two earlier audits exists in code, apart from the sessions `.gitignore` (fixed in #102), and the 07052b6 pattern did not recur. Two fixes are incomplete: the secret guard (S1) can be bypassed through symlinks (X1), and the markdown neutralization (G2) through reference-style links (X5). The dismissal rule (G1) can be bypassed through the summary state (X3). Some fixes have no test at all (#112).

Also found and already addressed:

- **Anchoring picks the wrong line or file.** A short partial quote anchors to the first line that contains it, and that line then decides "fixed". Cross-file matching moves a finding to another file, where it is dropped as "outside its bundle". Both confirmed by repro. #86 (`[needs-eval]`) already fixes most of this: it requires a unique partial match of at least 12 characters, and cross-file matches must be exact and unique.

## Questions for the maintainer

Both decided by the maintainer on 2026-09-27, as recommended: the judge never lowers a confirmed critical below critical (#116), and a critical finding left unchecked because Verify failed or was unaffordable makes the run exit 3 (#117).

1. **May the judge downgrade a confirmed critical finding?** It cannot drop one, but it can recalibrate it to `suggestion`. That clears `significant_concerns`, and the judge reads the attacker-controlled PR text. This is documented and tested as intended, but the code comment says the protection exists so the judge cannot "make a blocking finding disappear". Options: never lower a protected finding below critical, or let the downgrade change only how the finding is shown and compute the verdict from its pre-judge severity.
2. **Should an unchecked critical finding make the run incomplete?** When Verify fails, times out or is skipped for budget, a real critical finding stays `unchecked`, the verdict is `minor_issues` and the exit code is 0. That follows the rubric confirmed on 2026-09-26 (unverified criticals give `minor_issues`), but a run that could not check its blockers reads as a pass. Options: exit 3 when a critical finding is unchecked because Verify failed or was unaffordable (as opposed to `verify: false`), or leave it as it is.

## Checked and fine

- **Dependency direction and file size.** `core` imports nothing in-repo, adapters import only `core`, and only `cli` wires them together. No file exceeds 450 lines. There are no TODO markers.
- **Earlier fixes, beyond the gaps above.** The environment allowlist, the OpenCode isolation, the MCP token check, `--no-repo-config` for local runs and eval, terminal sanitizing, and the `extends` limits are all in place.
- **Exit codes.** The 0/1/2/3/130 ordering is correct for task outcomes. An interrupt returns 130 before publishing, and the runtime is disposed in a `finally`.
- **Verdict and Verify.** `decideVerdict` follows the rubric. Verify drops a finding only on an explicit `refuted`. Every LLM answer is validated with Zod. The judge cannot drop or merge away a protected finding.
- **Re-review.** `reconcile` calls a finding fixed only when its code is gone or the file is deleted. The incremental scope and its pending set match ADR-0010.
- **Budget.** The 80/20 split between reviews and Verify/Judge is enforced.
- **Run limits.** The failback circuit breaker, the quota waits, the step caps and the task and run timeouts all race the abort signal.
- **PR-mode trust.** Config, rules, memory and `AGENTS.md` are read from the base commit, and plugins never load.
- **Manual translations.** The English and Chinese manuals agree on every number and code token.
