# Security review of M2–M4, 2026-09-26

A focused follow-up to the [2026-09-26 self-audit](2026-09-26-self-audit.md), covering code added the same day: the review matrix, security and performance reviewers, Verify, Judge, the GitHub adapter and Action, re-review with thread resolution and dismissals, review memory, `--ultra` and `extends`. Threat model as before: the pull request's author, anyone who can comment on a public repository, and model output steered by the diff are all untrusted.

## Findings (all fixed in the same pull request)

| # | Finding | Severity |
|---|---|---|
| G1 | **Dismissals could bypass the check.** Any non-bot account that resolved one of ocra's threads, or replied "won't fix", dismissed the finding, and dismissed findings no longer count towards the verdict. The pull request's author can resolve threads on their own pull request, and on a public repository anyone can reply, so a critical finding could be resolved away and `fail-on-concerns` passed. Now only people other than the author count: resolvers (resolving requires write access) and repliers whose `authorAssociation` is `OWNER`, `MEMBER` or `COLLABORATOR`. | High |
| G2 | **Markdown from the diff and the model was not fully neutralized.** File paths (author-controlled) were put in code spans without escaping backticks, so a path could end the span and inject an image (a tracking pixel for everyone who opens the pull request). Model text could form links whose label differs from their target, in a comment the bot's identity makes look trustworthy. Paths now go through `codeSpan` (backticks and newlines replaced) and `safeMarkdown` breaks link syntax. | Medium |
| G3 | **Commit ids from the API reached `git fetch` unchecked.** A value such as `--upload-pack=…` would be read as an option. The API schema and `ensureCommits` now accept only 40- or 64-hex commit ids. | Low |
| G4 | **`extends` buffered the whole response before checking its size.** It now reads the body as a stream and stops at 256 KB. | Low |

## Checked and fine

- Trusted inputs in pull request mode (`.ocra/config.json`, `.ocra/rules.json`, `.ocra/memory.json`, `AGENTS.md`, `extends`) come from the base commit; repository plugins never load.
- Only ocra's own summary comment (marker plus author) carries state; forged threads are ignored for resolution and dismissal; the state block is validated and bounded.
- Verify and Judge prompts neutralize every untrusted section; their failures keep findings, so a hostile answer can drop at most what the verifier or judge was allowed to drop.
- `action.yml` passes inputs through environment variables only; `GITHUB_TOKEN` does not reach the OpenCode child (environment allowlist).
- Review memory cannot be changed by the pull request under review.

## Accepted risks

- Bare URLs in model text still autolink on GitHub; only labelled links and images are neutralized.
- `extends` can point at any https host, including internal ones reachable from CI; it is set by whoever controls the base branch, who can already change the workflow.
- A reviewer with write access can dismiss a critical finding. That is the intended escape hatch; the summary lists dismissed findings.
- Summary truncation at 60,000 characters can cut through the `<details>` block; rendering degrades, nothing leaks.
- The GraphQL fields used for G1 (`authorAssociation`, `resolvedBy`) are covered by tests with a faked API only; see `docs/pending-verification.md`.
