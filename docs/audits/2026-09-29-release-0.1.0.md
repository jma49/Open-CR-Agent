# Release audit, 2026-09-29 (0.1.0)

The audit of the release preparation before the first publish to npm: #233 on `main` at `602774b` (release tooling, workflow, package metadata, changelog, runbook) and the draft #234 (installation from npm). A published version can never be reused, so the question was what could make the publish fail, publish something wrong, leak something, leave a user with a broken install, or weaken the release workflow. It ran from a fresh clone, with npm pointed at an empty user configuration (anonymous) for everything that talks to the registry, and no model calls. Nothing was published.

Severity: **P0** exploitable or wrong in normal use · **P1** real weakness under realistic conditions · **P2** hygiene.

**Verdict: safe to publish** once this pull request is merged. No P0 or P1 finding; the P2 findings that change what gets published are fixed here, the rest in #234 or written down as follow-ups.

## Findings

| # | Finding | Confirmed by | Sev | Resolution |
|---|---|---|---|---|
| R1 | **The packages promised Node.js 22 while undici 8 needs 22.19.** The runtime uses undici 8 (`engines: >=22.19.0`); on an older Node 22 npm warns about undici, not about ocra. Metadata of a published version cannot change. | `npm view undici@8 engines` | P2 | `engines` is `>=22.19` in every package and the root; the changelog, the npm README and `AGENTS.md` say so here, the README and the manual in #234 |
| R2 | **The OpenCode build was chosen in a fixed order: default, baseline, musl.** The glibc builds declare no `libc`, so npm installs them on musl Linux too, and the resolver took the glibc build there; on x64 without AVX2 it took the AVX2 build. `opencode-ai`'s own install script orders by libc and AVX2, but ocra does not use it (npm 12 blocks it). | package manifests, code; not run (no container runtime here) | P2 | `binaryVariants` orders musl builds first on musl and baseline first without AVX2, as that script does; tests fail on the old order |
| R3 | **The npm README and the quickstart configured no `top` model**, so every review with findings warned that the judge failed. | code (`judge.ts`, `noModel`) | P2 | Both name `google/gemini-3.1-pro-preview`, as the configuration page, the README and the measured runs do |
| R4 | **npm 11.16 and later warn about `opencode-ai`'s install script on every install, and npm 12 blocks it.** Nothing told users whether to allow it. | installs with npm 11.19 and 12.1 | P2 | #234: the installation page says it is not needed |
| R5 | **The manual's introduction still said "early development".** | read | P2 | #234: "an early 0.x release" |
| R6 | **The release `pack` job runs `check:packages` before it packs the final tarballs.** That check installs the tarballs with dependencies resolved fresh from the registry, with install scripts, and runs the installed `ocra`; `npm ci --ignore-scripts` keeps only the lockfile install free of scripts. A dependency compromised after the lockfile was written would run in the job whose output is published. | code | P2 | Follow-up in `docs/releasing.md`: run the check in its own job after `pack` uploads the tarballs |
| R7 | **A re-run right after a partial publish can hit `E403`**: the registry may not list a version it just accepted, so the script tries it again. | npm behavior | P2 | `docs/releasing.md`: wait a minute and re-run |

## Checked and sound

- **Tarballs.** The five packages pack `dist` JavaScript and declarations, `package.json`, `README.md` and `LICENSE`: no tests, fakes, source maps, `.local` or env files, and no path from the build machine. Every manifest has the version 0.1.0, exact internal pins, `repository` with `directory` (as provenance requires), `publishConfig.access: public`, and no scripts. `cli`'s bin is `dist/main.js` with a shebang. `@open-cr-agent/eval` is private.
- **Installs, as a user.**
  - `npm install -g` of the five tarballs with npm 11.19.
  - The layout of `npm install -g @open-cr-agent/cli`, with every dependency nested under `cli`, and without install scripts.
  - `npm install -g` with npm 12.1.

  In each, `ocra --version` printed 0.1.0 and `ocra review --plan` planned a scratch repository. The installed runtime found the platform binary (never `opencode-ai/bin`), started OpenCode and the review tool server, and stopped both; the MCP server reported version 0.1.0. npm 12 left `opencode-ai`'s placeholder in place and ocra did not need it.
- **`scripts/release.mjs`.**
  - `--publish` runs `npm publish <tarball> --access public --tag latest` with inherited stdio, so npm's browser prompt for the security key appears. There is no `--provenance`, which would fail outside CI.
  - It publishes the tarballs it packed, after checking the name and version inside each, in dependency order (`core`, `runtime-opencode`, `vcs-github`, `vcs-local`, `cli`), and skips versions the registry has.
  - It refuses a dirty tree, a commit that is not on `origin/main`, packages out of lockstep, or a missing changelog section.
  - The dry run passed end to end in 30 seconds, with a user configuration holding only the maintainer's `allow-scripts` setting, which is what used to break `check:packages`. It failed at the end only on its refusal for a logged-out npm, as intended. The `EALLOWSCRIPTS` fix holds, and it hides nothing: the nested install still reads the setting from the user configuration.
- **`.github/workflows/release.yml`.**
  - Only the `publish` job has `id-token: write`. The runner does not log that permission ([actions/runner#3268](https://github.com/actions/runner/issues/3268)).
  - The four action pins match their tags' commits. No event data is interpolated into `run:`.
  - Publishing needs a tag equal to `v<version>`; a manual dispatch defaults to a dry run and refuses to publish from a branch. Prereleases go to `next`.
  - The publish job matches npm's documented trusted-publishing example: `setup-node` with `registry-url` and no `NODE_AUTH_TOKEN`, Node 24.21 with npm 11.19.
  - The CI dry run (run 36529835783) passed.
- **Runbook.**
  - The `npm trust github` flags match `npm trust github --help` on npm 11.19.1 (`--file`, `--repo`, `--allow-publish`, `--yes`), and no environment is used or passed.
  - The option to skip two-factor prompts for five minutes is npm's "remember me for 5 minutes" ([GitHub changelog, 2022-07-26](https://github.blog/changelog/2022-07-26-general-availability-of-improved-2fa-experience-in-npm/)).
  - `release.mjs notes 0.1.0` prints the changelog section for `gh release create --notes-file -`.
- **Changelog and #234.**
  - The changelog's claims match the code (30 steps, 60 tasks, the judge and verdict rules, the security boundaries), and it links to the quality page instead of restating numbers.
  - #234's English and Chinese pages match.
  - `npx @open-cr-agent/cli` runs the package's only bin.
  - `jma49/Open-CR-Agent@v0.1.0` builds the action from source at that tag.

## Not verified

- musl Linux, x64 without AVX2, and Windows: R2 follows `opencode-ai`'s install script and is covered by unit tests only.
