| [0011](0011-golden-eval-set.md) | Quality decisions on an ocra-owned golden set (expected findings, forbidden ranges, recorded adjudication); AACR-Bench stays the external number |

| [0015](0015-spend-limit-order-and-reporting.md) | Under a spend limit, tasks finish files in plan order so a pull request progresses across pushes; never-started tasks leave files unreviewed, and the report names the limit |
| [0016](0016-shared-review-conversation.md) | One review conversation for every platform in `vcs-platform` (trust rules, state, summary); GitLab second; line-leading slashes neutralized |
| [0017](0017-openai-compatible-providers.md) | Model providers declared in configuration: OpenAI-compatible endpoints, https, the key by variable name, a price for every model |
| [0018](0018-finding-specification.md) | The finding is the specification: one shared model with provenance (task, model, the task's cost), quote-anchored, three-valued verification; the JSON report is its published form, with a generated and tested JSON Schema |
| [0019](0019-sarif-import.md) | External findings enter as SARIF logs the CI job hands over; ocra runs no analyzer; only results on the change, as a synthetic task, verified and judged like a reviewer's |
| [0020](0020-direct-runtime.md) | A second runtime, `direct`: a tool loop over declared OpenAI-compatible endpoints, nothing else on the network; the runtime logic both share lives in core; a conformance suite every runtime passes |
| [0021](0021-reviewer-entity.md) | Proposed: the reviewer declares its tools; finding processors at two insertion points (after Execute, after Verify) that can keep, drop or downgrade with a recorded reason, never raise or add; `tools` can land now, processors with their first customer |
| [0022](0022-organization-policy.md) | Proposed: an organization policy named by `OCRA_POLICY` (pinned https or a runner file), never by the repository; it caps spend, allowed models, providers, runtimes, mandatory reviewers and excluded paths over every other layer, fails closed, and the report says what it did |
| [0023](0023-optional-opencode-runtime.md) | The OpenCode runtime is an optional dependency of the CLI, imported only when the configured runtime needs it; the Action's `opencode: false` installs without it (11 MB instead of 175 MB); no install cache |
| [0024](0024-ocra-cloud.md) | ocra Cloud: open core plus an optional hosted service on the published packages; Phase 1 is login (device flow), the user's own key kept in the cloud behind an allowlisted gateway that logs no bodies, metadata-only upload with content opt-in, and a web view; the hosted GitHub App is Phase 2, ocra-provided models Phase 3 |
| [0025](0025-per-agent-models-and-effort.md) | Models and reasoning effort per agent (reviewers, verifier, judge, helpers), in `.ocra/config.json` or as ocra Cloud account defaults layered under the repository's settings; runtimes map one level vocabulary to each provider and drop what a provider cannot express |
| [0026](0026-hosted-review-compute.md) | Proposed, deferred: hosted reviews for the ocra Cloud GitHub App in Cloudflare Containers (Cloud Run Jobs as fallback); GitHub Actions in an ocra-owned repository is ruled out by GitHub's terms (Sandbox SDK), one microVM per review, credentials injected outside the sandbox, egress limited to GitHub and the gateway; Cloud Run Jobs as the fallback |
| [0027](0027-account-configuration.md) | The review configuration's data settings (limits, verification, selection, rules, models) in the ocra Cloud account, under the repository's, versioned; never providers or extends; account-listed plugins load only from a per-machine install with its settings |
| [0028](0028-findings-upload-and-cloud-memory.md) | Per-reviewer counts in the default upload; findings uploaded only when the account turns it on (off by default, bounded, 90 days); the web shows full reviews and keeps memory in the account, applied under the repository's `.ocra/memory.json` |
| [0029](0029-committable-suggestions.md) | A finding may carry a `fix` (whole new-file lines and their replacement), rendered as a GitHub or GitLab committable suggestion only on an inline comment anchored to exactly those lines, posted exactly or not at all, and carried in the JSON report and SARIF; no stage sets it until an evaluated prompt change, since today's suggestion text cannot be turned into one safely |
| [0030](0030-task-ending-and-incomplete-coverage.md) | Revises ADR-0015 #2: every attempt has an ending (`done`, `step_cap`, `stopped_early`, `error`), read in core; a task that ends without the done tool leaves its files `incomplete` (partly reviewed), so the run exits 3 and the next review includes them |
| [0031](0031-reuse-completed-tasks.md) | A completed task records its reported findings under a key hashing its inputs; `ReviewOptions.resume` / `ocra review --resume` reuse matching tasks of an earlier run (and its bundles) instead of paying for them again; `ocra-eval --retry-failed` resumes. Amended 2026-10-09: only lines sealed with the user's own key are resumed; the key includes the commits |
| [0032](0032-verification-gates-blocking.md) | Only a critical finding Verify confirmed blocks (exit 1); one it could not check makes the review incomplete (exit 3), which outranks blocking; unconfirmed critical findings cap the verdict at `minor_issues` |
| [0033](0033-cloud-contract-package.md) | The CLI–ocra Cloud wire contract (schemas, limits, vocabularies, error codes, redaction) lives once in `@open-cr-agent/cloud-contract`, which depends on Zod alone so ocra Cloud runs it on Workers |
| [0034](0034-public-api-policy.md) | Each published package's main entry is a named export list recorded in `etc/<package>.api.md` and checked in CI; `/internal` is not a contract; the 0.x rule governs changes |
| [0036](0036-golden-case-set-policy.md) | Amends ADR-0011 points 1, 2, 3 and 5 and ADR-0014 point 4: golden sources in priority order (AACR-Bench comments people wrote, fresh held-out pull requests, ocra history at most 30% of smoke, forbid seeds, ReviewBench never held out); every case records licence (OSI allowlist) and head date, every claim an id, origin, producer and `optional`; at most 3 required and 5 optional claims and 3 forbid ranges per case; optional claims count for precision, never recall; a vetting protocol with a blind second rater |
| [0037](0037-review-learnings.md) | Review learnings are Markdown files with YAML frontmatter in `.ocra/learnings/`, read from the trusted revision, the schema in `cloud-contract`; selected per bundle before any model call (path, symbol, keyword; `critical` always on a path match; capped count and size), listed in the report, selection recall replayed and gated at 95% |
| [0038](0038-pull-request-identity-in-upload.md) | Amends ADR-0028: a `--pr` or `--mr` review adds `pullRequest` (the repository as `normaliseRemote` names it, number, head commit) to its upload; code stays opt-in and redacted; `normaliseRemote` moves to `@open-cr-agent/cloud-contract` |
| [0039](0039-code-graph.md) | Callers come from tree-sitter symbols per file (`@open-cr-agent/code-graph`, WASM, six languages), parsed lazily for the bundle and search candidates and cached by git blob id; a SCIP index the user supplies (`--scip`) answers first where it knows the symbol; ocra never builds one per pull request |
| [0040](0040-learning-sources.md) | Learning sources are `ocra learn` commands in the engine (fix-commit mining first), sharing one pipeline: draft on the helper role with validated symbols and derived paths, deduplicate, keep only what the selection replays to its own change, write the file; written back by a pull request that merges automatically unless `learnings.requireReview` is set |
| [0041](0041-repository-code-graph.md) | Amends ADR-0039 point 5: a revision's code graph keyed by language and blob id, updated by parsing only new blobs (`updateGraph`, no I/O of its own, bounded and abortable, skips recorded), a versioned deterministic file, callers by name after SCIP and before search (`--graph`), built by `ocra graph` or a server from trusted revisions only |
| [0042](0042-analyzer-evidence.md) | `--sarif-evidence` shows reviewers an analyzer's results on and near the change as data to confirm, selected per bundle before any model call (at most 20, change first, then severity and security tag), never as findings of their own; the report's `analyzerEvidence` says what was given; `--import-sarif` keeps ADR-0019 |
| [0043](0043-security-evidence-routing.md) | Amends ADR-0042 point 3: an analyzer result tagged `security` goes only to the security reviewer of its file, and to every reviewer of the file when no security reviewer reviews it |
| [0044](0044-learning-selection-recall.md) | Amends ADR-0037 point 4: learning paths follow `.gitignore`, a compound symbol matches in any naming convention and member-access syntax, keywords match plurals and unspaced scripts, evidence ranks before a bare path; the replay also gates listing, unrelated learnings and token cost, with property tests |
| [0045](0045-learning-ranking-by-changed-code.md) | Amends ADR-0044 point 4: when the limits leave a learning out, the code of the definitions the change touches (tree-sitter) ranks the learnings on the bundle's paths; it never adds a candidate or a token |
| [0046](0046-hosted-review-runner.md) | Amends ADR-0024: hosted reviews run on the self-hosted server: one enrolling account per repository pays, a webhook queues each head (newest wins), a leased worker runs the released CLI in pull request mode with `--no-repo-config` in a temporary clone it always deletes, and posts as the ocra bot (a per-job GitHub App installation token, or GitLab's bot token) |
| [0047](0047-change-walkthrough.md) | A walkthrough of the change, beside the review tasks: one standard-tier call on the new `writer` role over the selected diff (24,000 characters, smallest patches first); code keeps the files to the diff and a Mermaid sequence diagram to an allowlist; on for `--pr`/`--mr`, in the summary comment (folded) and the report |
| [0048](0048-answering-mentions.md) | Answering an `@ocra` mention in its thread: `ocra reply` per comment; the conversation rules (write access, unedited, once per comment) in `vcs-platform`; one `writer` call over context code chooses from the review's selection, never an agent with tools; the Action's `reply` input |
| [0049](0049-sensitive-bundles-first.md) | Amends ADR-0015 decision 1: bundles that touch a sensitive path (triage's test) run first, plan order within each group; the spend limit, the task limit and `--plan` share that order; task ids keep the bundle's plan position |
| [0050](0050-mcp-server.md) | `ocra mcp` serves one `review` tool over MCP on stdio, taking only `ocra serve`'s narrowing request (shared schema, unknown arguments refused); the answer is marked as untrusted data; one review at a time, cancellable, with progress; the MCP SDK is an optional dependency imported on use; no delegate mode yet |
| [0051](0051-generated-commits.md) | `ocra generate tests` and `ocra generate docstrings`: one `writer` call per changed source file (at most 5) from the review's selection; code decides every path and position and refuses anything but new test files and inserted doc comment lines; one commit on the change request's branch, only on the head ocra read (`VcsAdapter.commit`, rules in `vcs-platform`); forks and moved branches are outcomes; nothing from the repository runs |
| [0052](0052-task-context.md) | The linked task as review context: the issues the platform links to the change (GitHub closing issues, GitLab `closes_issues`, else the issue the branch is named after), of the reviewed repository only, at most 3 with fixed cuts, in the shared prompt prefix as data; `linkedTasks` switch and report entry; Jira and TAPD through the team's MCP server (`trackers`), keys of its own projects only; project documents planned |
| [0053](0053-stacked-changes.md) | Stacked change requests: parents recorded in the clone's git config, no server state; restack by `rebase --onto` from the recorded parent head (squash merges drop out); `submit` pushes with a lease and writes the stack's list between markers; `sync` folds in merges and never pushes; `StackHost` port in `vcs-platform`; ocra Cloud reads stacks from base/head chains and merges from the bottom |
| [0054](0054-pre-merge-checks.md) | Pre-merge checks in plain words: `mergeChecks` in the configuration (the contract's shape, ids naming the text); one top-tier `judge` call beside the review tasks gives each `passed`, `failed` or `inconclusive` with a reason; outcomes go to the summary comment, the report and the upload, never the exit code; the upload also names the learnings given |
| [0055](0055-noise-baseline-and-held-out-set.md) | The noise baseline: `ocra-eval noise` splits one setup's 4 to 10 repeats into halves every way and judges each with `verdict` (A/A: no split may be worse), giving the smallest margin every split passes at; a registry of baselines (`--register`); `run --dry-run` prints reviews and spend bound without spending; amends ADR-0036 point 3: code the maintainer owns (`LicenseRef-maintainer-owned`) only in the private held-out set |
| [0056](0056-live-review-relay.md) | A signed-in review whose account shares findings relays its `ReviewEvent`s to ocra Cloud as it runs (`POST /api/live`, `liveBatchSchema`), best effort and never in the review's way; stored by run and seq, first write wins; the owner shares a run per person or by one link, as viewer or commenter, to people signed in to the server; comments belong to the run and may point at a finding; watching is polling behind Server-Sent Events, the same on Workers and Node |
| [0057](0057-review-context-budgets.md) | The review prompt is built as parts, one context source each; `ocra review --plan` counts each part (tokens, cuts, duplicated lines) and `ocra-eval context` sums them over the golden set for free; every source has a token budget in a test, with new caps on the changed-files list, accepted findings, repository rules and titles; `ocra review --without <sources>` (and `ocra-eval run --without`) leaves sources out for the per-source ablation |
| [0058](0058-checked-fix-proposals.md) | Amends ADR-0029 point 2: a fix stage after the judge proposes a fix for findings anchored to the change, one `fixer` call per file (no tools), each checked by code (quote still at head, only the anchored lines, no control characters, size, tree-sitter parses no worse) and dropped on failure; off unless `fixes`, `--fixes` or the account asks; `ocra-eval run --fixes` counts them |
| [0059](0059-guideline-sections.md) | `AGENTS.md` is read as whole sections and never cut mid-section: what does not fit 20,000 characters is left out whole and listed by heading; a heading that names a path scopes its section and subsections; `guidelineScope` / `--guidelines`: `all` (default), `matched` (sections for the bundle's files) or `reviewer` (only `agents-md`, which always gets every section); amends ADR-0057 |
| [0060](0060-golden-team-context.md) | Golden cases may carry learnings and project documents (`context`): learnings are committed onto the base with the range replayed on top, documents go through `--config`; linked tasks stay synthetic until a local input exists |
| [0061](0061-review-performance-budget.md) | `ocra-eval perf` reviews a local range with the real CLI and a scripted model and reports wall time, CPU, memory, git processes and the requests and input tokens of each model call; a test holds a synthetic change to `evals/perf-budget.json`; one `git grep` runs at a time, shared by the searches that wait and stopped once each has its matches; the direct runtime runs a step's tool calls together |
| [0062](0062-direct-messages-wire.md) | Amends ADR-0020: a declared provider is `openai-compatible` or `anthropic`; the direct runtime's loop runs over a wire per protocol, and the Messages wire goes through Anthropic's SDK, streamed, with the prompt cache at every step and effort as `output_config.effort`; the CLI declares an ocra Cloud provider by Messages where it lists no chat completions; the OpenCode runtime refuses a declared `anthropic` provider |
| [0063](0063-done-tool-ends-the-session.md) | On the OpenCode runtime the done tool asks for a permission that ocra rejects, which ends the session with the step's usage recorded: no request follows the done tool (one fewer per task, about a fifth fewer input tokens); the conformance suite counts the requests |
| [0064](0064-review-input-tokens.md) | What a migration tool writes next to its migrations (Drizzle snapshots and journals, Prisma's lock, EF Core's designer files and model snapshot) is generated and not reviewed, as are more lock files; a review task says where the start it shares with the run's other tasks ends (`AgentTaskSpec.sharedPrefixes`), and the Messages wire marks it for the prompt cache, so later tasks read it instead of storing it again; amends ADR-0062 |
| [0065](0065-whole-change-reviewers.md) | A reviewer's scope may span the change (`span: "change"`): the matrix gives it the change in as few tasks as 20 files and the bundle size limit allow, after the per-bundle tasks; the docs and agents-md reviewers do |
| [0066](0066-plan-call-as-the-reviewer.md) | A task's plan call is asked as its reviewer: the reviewer's system prompt and the task's prompt up to the end of the files, ending with the request for a checklist; a completion may name the starts a task opens with too (`CompletionRequest.sharedPrefixes`), and the direct runtime then sends it with the review tools and stores those starts, so the task reads its files from the prompt cache |
| [0067](0067-review-wall-time.md) | A review's time is its model requests divided by the tasks running at once, so eight run by default instead of four; a rate limit no longer costs a task its progress: the direct runtime waits the model's shared pause out inside the attempt and sends the refused request again (`RateLimits.waitOut`) |
| [0068](0068-packed-reviewers.md) | A reviewer's scope may pack bundles (`span: "packed"`): the matrix gives it bundles that follow each other in run order in one task, up to the bundle size limits, never mixing sensitive and other bundles; the security and performance reviewers do |
| [0069](0069-learning-from-declined-findings.md) | `ocra learn feedback --pr`/`--mr` also drafts from the findings of the earlier review that someone with write access declined in their thread, with what they said (`ChangeRequest.declined`); the author counts, as with `/ocra remember`, since nothing leaves the verdict and the learning goes through a pull request |
| [0070](0070-tool-calls-as-text.md) | The direct runtime can carry tool calls as text for a chat completions endpoint that takes no `tools`: the tools go in the system prompt, the model writes `<tool_call>` blocks, results come back as data in `<ocra_tool_result>` sections; chosen by `providers.<id>.toolCalls: "text"` or when the endpoint refuses the tools; the loop, caps and checks are unchanged; the OpenCode runtime refuses such a provider |
| [0071](0071-context-window.md) | A model may declare its context window (`providers.<id>.models.<model>.contextWindow`): the plan holds a task's diff to a quarter of the smallest declared window, the direct runtime ends a conversation before the request that would not fit (wrap-up turn, then `ended: context_window`, a third incomplete ending) and does not send a prompt that cannot fit; the context around the diff is not scaled; nothing changes without a declaration |
| [0072](0072-one-task-stores-a-shared-start.md) | On the Messages wire a conversation's first request waits until the answer to another that is storing the same start has begun (`SharedStarts`): tasks that start together read the start one of them stored instead of each storing it; the wait ends after ten seconds or when that request ends without an answer |
| [0074](0074-early-findings.md) | Verify starts while tasks run: a file's findings are checked once every task reviewing it has ended, and a finding is verified once; a critical finding the verifier confirms is settled (the judge can neither drop, downgrade nor merge it away) and is sent as such (`findings_verified`, `settled` on the wire), so it can be shown as a result before the run ends; everything else waits for the judge |
| [0075](0075-plan-call-for-bundle-reviewers.md) | Outside `--ultra` only a reviewer with a task per bundle plans a large bundle first; reviewers that take the change whole or in packed bundles do not: their plan calls were a tenth of a review's bill and changed no result |
| [0076](0076-inline-comment-policy.md) | `minInlineSeverity` and `maxInlineComments` (and `--min-inline-severity`, `--max-inline-comments`) choose which findings a platform posts inline: below the floor or past the cap, ranked by severity, Verify's answer, confidence, then place, a finding is listed in the summary instead and stays in the report (`inline.held`); `ultra` is a configuration key and `--no-ultra` turns it off over the account's |
| [0077](0077-fix-one-finding.md) | `ocra fix` writes a checked fix for one stored finding (`sharedFindingSchema` in, `fixResultSchema` out): anchored again at the head by the review's rules, the fix stage's candidate rules but for having a fix, one fixer call through `proposeFixes` and `checkFix`; never commits; exits 3 when the finding's code is gone or the head moved |
| [0078](0078-fix-loop.md) | `ocra mend` runs one round of a fix loop per event (accepted findings, failed checks, conflicts, reviewers' requests): edits on an in-memory overlay by the fixer completion or a tool loop with one `edit` tool, a scope gate in code, a verifier call, one unforced commit; nothing from the change runs, the change request's own CI is the test; capped attempts, rounds and spend; never approves or merges; `off`, `propose` or `commit` per repository |
| [0079](0079-merge-conflicts-as-a-merge-commit.md) | `ocra mend --conflicts` reads the conflicts of merging the base branch from the clone's object store, has the fixer answer each conflicted region while code writes the file, and writes all of them or none: proposed by default, or one merge commit with both parents pushed from the runner's clone without force; never a rebase |
| [0080](0080-findings-name-their-rule.md) | Every repository rule has an id (`rules.json` `id`, a `rules.md` heading, else `rule-` and a hash of its text), the prompt shows rules under it, `report_finding` takes an optional `rule` that code keeps only when the task was given that rule or learning, and the report and the Cloud upload carry `rule: { kind, id }` |
| [0081](0081-review-trace.md) | Every review builds a trace from its own events (stages, tasks and timed attempts, every plain model call with its model, each reported finding's fate and reason), keeps it as `trace.json` beside the report, and sends it to ocra Cloud with the findings, redacted and bounded; no code, prompt, answer or searched text |
| [0082](0082-performance-reviewer-at-full-tier.md) | The built-in performance reviewer runs at the `full` risk tier, and at `lite` only on bundles with a hot-path file (it ended every one of 80 smoke tasks without reading or reporting anything, 6-10% of the bill); `reviewers.performance.minTier` sets one tier for both |
| [0083](0083-codex-runtime.md) | A third runtime, `codex`, reviews on the user's own Codex sign-in: one `codex exec` per attempt with ocra's tools over MCP, Codex's own tools, config, rules and history left out, no API key passed, tokens reported at $0, a usage limit counted as a daily quota; no resume or wrap-up turn |
